# Устранение неполадок

Во всех ручных проверках указывайте рабочий префикс:

```sh
docker exec angie angie -p /data/conf -c angie.conf -t
docker exec angie angie -p /data/conf -c angie.conf -T
```

Голый `angie -t` проверяет пакетный префикс, а не обязательно собранное рабочее
дерево.

## 1. Порт занят

Измените порт хоста. Внутренний порт остаётся 80 у обычного образа и 8080 у
непривилегированного:

```sh
docker run -p 8081:80 6run0/angie:alpine
docker run -p 8081:8080 6run0/angie:alpine-unprivileged
```

## 2. Запросы возвращают 444

Встроенный catch-all намеренно закрывает запросы, не совпавшие со своим
`server_name`. Добавьте server в `/etc/angie/custom/http.d`. `/healthz`
доступен только с loopback и возвращает 404 остальным клиентам.

## 3. Настройка `ANGIE_*` не действует

### Контейнер перезапущен, а не пересоздан

Docker не меняет окружение контейнера при `docker restart`. После правки
переменных пересоздайте его (`docker compose up -d --force-recreate`). Restart
повторно запускает entrypoint, но со старыми значениями.

### Своя конфигурация заменяет или дублирует функцию

Выведите полное рабочее дерево командой `-T` выше. `add_header` во вложенном
контексте заменяет унаследованные заголовки. Свой `log_format`, map или listener
также может конфликтовать с управляемым образом.

## 4. `/data` недоступен для записи

**Симптом:** старт сообщает, что `/data` не записывается.

С корнем только для чтения подключите единственную изменяемую точку:

```sh
docker run --read-only --tmpfs /data:mode=1777 6run0/angie:alpine
```

Для ACME используйте `-v angie-data:/data`. Монтировать только `/data/conf` не
поддерживается.

## 4b. Том `CACHE_DIR`

**Симптом:** прокси-кеш падает с ошибками прав во время работы.

**Причина:** если задана `CACHE_DIR`, скрипт `90-fix-cache-permission.sh` при
старте передаёт содержимое каталога `angie`, пропуская символические ссылки.
Он работает только в обычном образе под root; непривилегированный образ
пропускает его с уведомлением.

**Решение:** для обычного образа смонтируйте каталог с правом записи:

```sh
docker run \
  -e CACHE_DIR=/var/cache/angie/proxy \
  -v /host/cache:/var/cache/angie/proxy \
  6run0/angie:alpine
```

Для непривилегированного образа смените владельца на хосте до монтирования:

```sh
chown -R 65532:65532 /host/cache
docker run --user 65532:65532 \
  -e CACHE_DIR=/var/cache/angie/proxy \
  -v /host/cache:/var/cache/angie/proxy \
  6run0/angie:alpine-unprivileged
```

Символическая ссылка внутри кеша остаётся со своим владельцем.
Файлы htpasswd исправляются так же, но только в `/etc/angie/custom`; на томе
только для чтения точка входа лишь предупреждает, поэтому сделайте их
читаемыми для `angie` на хосте.

## 5. `/data/conf` принадлежит другому UID

Entrypoint не пересобирает рабочее дерево другого UID. Это защита от
перезаписи чужих файлов. Запустите контейнер с прежним UID, возьмите свежий том
или исправьте владельца отдельным root-контейнером. Не добавляйте приложению
привилегии `chown` только для обхода проверки.

Непустой `/data/conf` без служебного маркера образа тоже вызывает отказ.
Очищайте его только после проверки, что пользовательских данных там нет; свои
файлы должны находиться в `/etc/angie/custom`.

## 6. Пользовательская конфигурация молча отсутствует

Подключаются только маски:

```text
/etc/angie/custom/conf.d/*.conf
/etc/angie/custom/http-conf.d/*.conf
/etc/angie/custom/http.d/*.conf
```

Файл в корне тома игнорируется. Каталоги должны быть проходимы, файлы - читаемы
runtime/worker-UID. Нечитаемая маска может выглядеть пустой без ошибки Angie.
Обычные безопасные права публичной конфигурации: 0755 для каталогов и 0644 для
файлов; для секретов используйте более строгие права и владельца.

## 7. Reload не работает

`angie -s reload` требует pid-файл, а образ использует `pid off`. Проверьте
рабочее дерево и отправьте сигнал контейнеру:

```sh
docker exec angie angie -p /data/conf -c angie.conf -t
docker kill -s HUP angie
```

Это перечитает `/etc/angie/custom`, но не изменит окружение контейнера. После
правки env пересоздайте контейнер.

## 8. Переменные GeoIP2 пусты

`GEOIP2_DB_COUNTRY` должен указывать на смонтированный читаемый обычный файл.
В пути разрешены `A-Za-z0-9._/-`. Форматы access log с GeoIP2 игнорируются,
пока база не активна. Выведите рабочую конфигурацию через `-T` и найдите
`geoip2`.

## 9. ModSecurity ничего не блокирует

Образ содержит движок, но не набор правил. Смонтируйте правила и подключите их
из своей конфигурации. Один `ANGIE_MODSECURITY_ENABLED=yes` ничего не фильтрует.

## 10. Console Light роняет старт или возвращает 401

Проверьте:

- `ANGIE_CONSOLE_PATH` содержит минимум 16 разрешённых символов без `/`;
- `ANGIE_CONSOLE_HTPASSWD_FILE` - абсолютный непустой читаемый файл;
- worker `angie` обычного образа, а не только root-мастер, читает его;
- запрос использует секретный путь и правильный basic auth.

`ANGIE_CONSOLE_HTPASSWD_FILE=none` снимает аутентификацию; не используйте это на
незащищённом слушателе. Поставьте TLS перед Console.

## 11. ACME постоянно заказывает сертификаты

`/data/acme` не сохраняется: обычно `/data` находится в tmpfs или контейнер
пересоздан без прежнего тома. Подключите постоянный том и сохраняйте его при
обновлениях. Сначала проверяйте настройку на тестовом CA.

Для HTTP-проверки публикуйте порт хоста 80 на публичный порт образа. Обычный
образ использует 80, непривилегированный - 8080 и запрещает внутренний порт
проверки ниже 1024.

## 12. ACME-проверка сбрасывается или перенаправляется

Используйте один HTTP-слушатель для обычного редиректа и ACME. Обработчик ACME
срабатывает до rewrite, поэтому отдаёт токен, пока остальные запросы уходят на
HTTPS. Отдельный challenge-порт без своего server может сбрасывать все запросы,
кроме живого токена.

DNS и ALPN требуют дополнительной настройки DNS/сети, которую образ не готовит.

## 13. HSTS остался после выключения тумблера

Браузер кеширует HSTS. Снова включите его с `ANGIE_HSTS_MAX_AGE=0`, отдавайте
заголовок по исправному HTTPS достаточно долго, затем выключите тумблер.
Удаление заголовка на сервере не очищает состояние клиентов.

## 14. Изменённый файл остаётся старым или даёт 404

Отключите `ANGIE_OPEN_FILE_CACHE_ENABLED` на время диагностики. Дескрипторы и
отрицательные результаты поиска могут кратковременно кешироваться. Для
версионных имён подключайте `snippets/cache-busting.conf`, только если
существует соответствующий файл без версии.

## 15. Контейнер завершается кодом 137 при stop

Docker отправил SIGKILL после истечения grace period. Держите
`ANGIE_WORKER_SHUTDOWN_TIMEOUT` (по умолчанию `8s`) меньше
`stop_grace_period` и оставьте время активным соединениям. Для мягкой остановки
используйте SIGQUIT/обычный stop контейнера.

## 16. Сообщения entrypoint отсутствуют

Любое непустое `ANGIE_ENTRYPOINT_QUIET_LOGS` скрывает все сообщения, включая
ошибки. Снимите переменную на время диагностики. По умолчанию используется JSON;
`ANGIE_ERROR_LOG_JSON_ENABLED=no` возвращает читаемый текст.

## 17. Сборка конфигурации завершается ошибкой

Entrypoint отказывает, если упал скрипт настройки или итоговая проверка рабочего
дерева. Прочитайте первую JSON-запись уровня `error`, затем воспроизведите
командой `-t` в начале документа. Контейнер намеренно останавливается, а не
обслуживает частично применённую конфигурацию.

## 18. Контейнер убит OOM

**Симптом:** контейнер завершается со статусом 137, а в журнале ядра OOM killer
забирает мастер или рабочий процесс Angie.

**Причина:** `angie.conf` задаёт `worker_rlimit_nofile 65536` и в `events {}`
`worker_connections 32768`. Каждый рабочий процесс при старте выделяет свой
массив соединений, поэтому память растёт с числом процессов, а
`worker_processes auto` считает процессоры по маске affinity (`--cpuset-cpus`),
а не по квоте `--cpus`. При жёстком `-m` OOM killer может сработать ещё до
нагрузки.

**Починка:** ни одну из директив через пользовательский том не переопределить.
Повторное объявление в `custom/conf.d` роняет старт с
`"worker_rlimit_nofile" directive is duplicate`, в `custom/http-conf.d` - с
`"worker_connections" directive is not allowed here`. Работают два пути.

Сократить число рабочих процессов. Одна `--cpus` этого не делает: измерено на
хосте с 16 CPU (Docker 29.9.0, образ 1.12.4 Alpine, 2026-10-23),
`--cpus 2 -m 256m` запустил 16 рабочих процессов. Любой из двух вариантов ниже
запустил 2:

```sh
docker run --cpus 2 -m 256m \
  -e ANGIE_ENTRYPOINT_WORKER_PROCESSES_AUTOTUNE=1 6run0/angie:alpine
docker run --cpuset-cpus 0-1 -m 256m 6run0/angie:alpine
```

Или подменить весь `angie.conf`, если нужны другие лимиты:

```sh
docker run -m 256m -v /path/to/angie.conf:/etc/angie/angie.conf:ro \
  6run0/angie:alpine
```

Цена второго пути: список включений становится вашим. Свой файл обязан
повторить все `include` поставляемого (`modules.d`, `conf.d`, `http-conf.d`,
`http.d` и их пары в `/etc/angie/custom`), иначе перестанут работать тумблеры и
пользовательский том; в `conf.d` лежат `user angie` обычного образа и
`pid off`. Монтирование `:ro` не мешает: файл копируется в `/data/conf`, и
скрипты правят копию. Три строки держите в поставляемом виде, если нужны их
переменные: `30-tune-worker-processes.sh` ищет `worker_processes`,
`31-error-log-json.sh` - `error_log /dev/stderr;` или
`error_log /dev/stderr format=json;`, `32-worker-shutdown-timeout.sh` -
`worker_shutdown_timeout <число>[ms|s|m];`. Строка, записанная иначе, не
правится: два последних скрипта предупреждают и идут дальше, первый молчит.

## 19. `exec format error` или нет подходящего манифеста

**Симптом:** контейнер сразу завершается с сообщением, оканчивающимся на
`exec format error`, или `docker pull` сообщает, что для платформы хоста нет
подходящего манифеста.

**Причина:** архитектуры хоста нет в манифесте образа. Публикуются только
`linux/amd64` и `linux/arm64`, см.
[limitations.ru.md](limitations.ru.md#10-поддерживаемые-платформы).

**Починка:** на другой архитектуре соберите образ локально
(`docker build -t angie-alpine -f alpine/Dockerfile .`) или запускайте
опубликованный под эмуляцией, если на хосте есть обработчик `binfmt_misc` для
неё (`docker run --platform linux/amd64 6run0/angie:alpine`).

## 20. `angie -t` или `angie -T` показывает не ту конфигурацию

**Симптом:** внутри контейнера `angie -T` не показывает сниппетов, включённых
тумблерами, `angie -t` проходит на заведомо сломанной конфигурации, или правка
через `angie-ctl` не видна.

**Причина:** вкомпилированный префикс - `/etc/angie` (см. `angie -V`), шаблон
только для чтения. Обслуживает запросы дерево `/data/conf`, его выбирают ключи
`-p` и `-c` в `CMD`. Голые `angie -t` и `angie -T` читают шаблон, то есть
конфигурацию, которую никто не исполняет.

**Починка:** используйте обёртку, которая добавляет рабочий префикс, или полную
форму:

```sh
docker exec <container> angie-runtime -t
docker exec <container> angie-runtime -T
docker exec <container> angie -p /data/conf -c angie.conf -T
```

Точная команда есть в метаданных образа:
`docker inspect -f '{{json .Config.Cmd}}' 6run0/angie:alpine`. `angie-ctl`
ключей не требует: образ задаёт `ANGIE_ETC=/data/conf` и
`ANGIE_BIN=/usr/local/bin/angie-runtime`.

## 21. Проксирование на `https` падает на проверке сертификата

**Симптом:** `proxy_pass https://...` отдаёт `502`, а в логе ошибок стоит

```text
upstream SSL certificate verify error: (20:unable to get local issuer certificate)
```

хотя `curl` с хоста до того же адреса проходит, а хранилище корневых
сертификатов в образе есть: `/etc/ssl/certs/ca-certificates.crt` (118 корней в
образе 1.12.4 Alpine и 148 в Debian, подсчитано 2026-10-23).

**Причина:** обычно не хранилище, а глубина цепочки.
`proxy_ssl_verify_depth` по умолчанию равен 1, а современная публичная цепочка
длиннее. Измерено 2026-10-23 на образе 1.12.4 Alpine для
`https://letsencrypt.org/` (4 сертификата в отдаваемой цепочке): глубина по
умолчанию дала `502` с ошибкой выше, глубина 2 - `200`.

**Починка:** разрешите настоящую длину цепочки:

```nginx
location / {
  proxy_pass https://upstream.example;
  proxy_ssl_verify on;
  proxy_ssl_verify_depth 3;
  proxy_ssl_name upstream.example;
  proxy_ssl_server_name on;
  proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
}
```

Длину цепочки конкретного апстрима видно снаружи:

```sh
echo | openssl s_client -connect upstream.example:443 \
  -servername upstream.example -showcerts 2>/dev/null | grep -c 'BEGIN CERT'
```

`proxy_ssl_trusted_certificate` обязателен: системное хранилище само не
подхватывается, и старт падает с
`[emerg] no proxy_ssl_trusted_certificate for proxy_ssl_verify`.

## 22. `SSL alert number 80` при включённом ACME

**Симптом:** контейнер работает, TLS-слушатель поднят, `angie -t` при старте
прошёл, но каждое рукопожатие обрывается. Клиент пишет

```text
SSL routines:ssl3_read_bytes:tlsv1 alert internal error
SSL alert number 80
```

`curl` показывает это как `error:0A000438`, браузер - как
`ERR_SSL_PROTOCOL_ERROR`.

**Причина:** сертификат ещё не выписан, и `$acme_cert_<имя>` пуста. Пустая
переменная законна для `angie -t`, поэтому старт этого не ловит. Окно между
первым стартом и первой выдачей есть всегда; пока оно открыто, редирект с HTTP
ведёт на TLS-слушатель, который ничего не отдаёт.

**Починка:** посмотрите, что клиент получил от CA:

```sh
docker logs <container> 2>&1 | grep '"acme_client"'
docker exec <container> ls -l /data/acme/le/
```

Вместо `le` подставьте `ANGIE_ACME_CLIENT`. Непустой `certificate.pem` значит,
что причина в другом; до первой выдачи файл есть, но размером 0. Частые строки
лога:

- `request to ACME server failed`: каталог CA недостижим. Проверьте
  `ANGIE_ACME_DIRECTORY` и выход наружу из контейнера;
- `no resolver configured`: в своей конфигурации стоит `resolver off;`.
  Умолчание `conf` ACME устраивает, `off` его выключает, см.
  [configuration.ru.md](configuration.ru.md#разрешение-dns-имён);
- отказ проверки: CA не получил `/.well-known/acme-challenge/...`. Убедитесь,
  что порт хоста 80 опубликован на `ANGIE_ACME_HTTP_PORT` (`-p 80:80` у
  обычного, `-p 80:8080` у непривилегированного), а домен ведёт на этот хост.

## 23. `ACME module will use port 80 for HTTP challenges, superuser required`

**Симптом:** это предупреждение появляется в непривилегированном образе. Под
runtime, где uid 65532 не может занять порт ниже 1024 (Kubernetes, голый runc),
старт затем падает на `bind()`.

**Причина:** предупреждение называет не ту починку. `acme_http_port` по
умолчанию 80, в непривилегированном образе этот порт никто не слушает, и модуль
открывает свой слушатель. Сообщение появляется только при своём `acme_client` в
`custom/http-conf.d` без `ANGIE_ACME_ENABLED`: тумблер сам ставит
`acme_http_port` равным публичному порту и в непривилегированном образе
отвергает значения ниже 1024. У обычного образа мастер под root и порт 80
слушается, поэтому предупреждения там нет.

**Починка:** включите `ANGIE_ACME_ENABLED` или добавьте в свой сниппет
`acme_http_port 8080;`, совпадающий с уже объявленным слушателем. Тогда модуль
своего слушателя не открывает, а проверку обслуживает существующий
`server {}`: обработчик стоит на фазе `post_read`, раньше `rewrite`, поэтому
даже сервер, который делает только `return 301` на HTTPS, отдаёт токен. Без
тумблера задайте ещё `acme_client_path /data/acme;`: каталог состояния по
умолчанию мастеру не от root недоступен для записи, и старт падает с
`mkdir() "/var/lib/angie/acme/<name>" failed (13: Permission denied)`.

Не выносите проверку на отдельный порт: собственный слушатель модуля обрывает
всё, что не живой токен, включая редирект с HTTP на HTTPS.

## 24. Приложение за прокси потеряло свой `Cache-Control`

**Симптом:** бэкенд отдаёт `Cache-Control: max-age=60, public`, а клиент
получает `no-cache` или срок в год. Код ответа `200`, в логах ничего.

**Причина:** директива `expires` попала в проксирующий `location`, например
`snippets/expires-by-type.conf` подключён на уровне `server`. `expires` не
дополняет заголовки апстрима, а заменяет `Cache-Control` и `Expires`: ответ
`text/html` по карте типов получает `epoch`, то есть `no-cache`.

**Починка:** подключайте `snippets/expires-by-type.conf` только в тот
`location`, который отдаёт статику, и никогда в тот, где стоит `proxy_pass`:

```nginx
location /static/ {
  include snippets/expires-by-type.conf;
}

location /api/ {
  proxy_pass http://backend:8000;
}
```

`expires off;` внутри `location` снимает унаследованную директиву точечно.

## 25. Заголовки безопасности пропали в моём `location`

**Симптом:** `ANGIE_SECURITY_HEADERS_ENABLED` включён, на одних путях
заголовки есть, на других нет. `angie -T` показывает все `add_header` на месте.

**Причина:** наборы `add_header` не объединяются между уровнями. `server` или
`location` с любым своим `add_header`, даже про посторонний заголовок, заменяет
унаследованный набор. Измерено на образе 1.12.4 Alpine (2026-10-23):
`location` с одной строкой `add_header Cache-Control "nested-only";` отдал

```text
HTTP/1.1 200 OK
Content-Type: application/octet-stream
Cache-Control: nested-only
```

а соседний `location` без своего `add_header` отдал
`X-Content-Type-Options: nosniff`. Ключ `always` ни при чём: он про коды
ответа, а не про наследование. `expires` - не `add_header`, поэтому
`snippets/expires-by-type.conf` замену набора не вызывает.

**Починка:** повторите нужные заголовки в том блоке, где объявили свой; режима
"добавить к унаследованным" у `add_header` нет.

Не путайте это с отбором по типу содержимого: `Referrer-Policy`,
`X-Frame-Options` и `Permissions-Policy` уходят только документам, стилям и
подобным типам, см. `055-security-headers.conf`. Отличие: при замене набора
пропадает и `X-Content-Type-Options`, а он отдаётся ответу любого типа.

## 26. `IPv6 is unavailable` в журнале старта

**Симптом:** строка уровня `notice`:

```text
IPv6 is unavailable; the built-in listener serves 0.0.0.0:80 only
```

с `8080` в непривилегированном образе.

**Причина:** в ядре нет IPv6 (собрано без него или загружено с
`ipv6.disable=1`; признак - нет `/proc/net/if_inet6`). Точка входа удаляет
встроенную строку `listen [::]:<port>` из рабочей копии, иначе старт упал бы с
`(97: Address family not supported by protocol)`. Это не ошибка.
`sysctl net.ipv6.conf.all.disable_ipv6=1` сюда не ведёт: сокет IPv6 при нём
создаётся, и строка остаётся.

**Что остаётся на вас:** строки `listen [::]` в пользовательском томе точка
входа не трогает, и на таком ядре они роняют старт той же ошибкой `97`. Для
такого хоста держите файлы без IPv6-слушателей.
