# Безопасность и запуск без root

Модель привилегий и усиление обоих вариантов образа.

## Модель пользователей

| Свойство | Обычный | Непривилегированный |
|---|---|---|
| Master-процесс | root | uid/gid 65532 по умолчанию; поддержан произвольный UID |
| Worker-процесс | пакетный пользователь `angie` | тот же UID, что у master |
| Публичный HTTP-порт | 80 | 8080 |
| Capabilities | сохранить стандартный набор Docker для root-master | нет |
| Рабочая конфигурация и временные файлы | `/data/conf`, `/data/tmp` | `/data/conf`, `/data/tmp` |

Оба варианта используют один неизменяемый шаблон `/etc/angie` и одинаковые
тумблеры. Обычный образ сохраняет классический root-master для привязки порта
80, а worker запускает как `angie`. Непривилегированный образ убирает директиву
`user` и работает под любым UID; его стандартная учётная запись - 65532.

В стандартном образе `/data` принадлежит root с режимом 0755: worker не может
писать рядом с временными каталогами, которые ему передаёт мастер под root.
Непривилегированный образ создаёт `/data` с режимом 1777, чтобы дерево мог
собрать любой runtime-UID. Точка входа не заменяет непустой `/data/conf`,
который создала не она, и отказывает для дерева другого UID. Это не позволяет
произвольному runtime-UID перезаписать чужую конфигурацию. При смене UID
возьмите новый том или исправьте владельца.

## Запуск под другим UID

Непривилегированному образу право на запись нужно ровно в одном месте,
`/data`, и он создаёт его с режимом 1777. Поэтому `docker run --user <любой
uid>` применяет тумблеры `ANGIE_*` так же, как uid 65532 по умолчанию, без
урезанного набора функций. Условие одно: `/data` должен быть записываем для
этого UID. Под `--read-only` без монтирования `/data` старт отказывает кодом 1
и сообщением, где названы `--tmpfs /data` и `-v angie-data:/data`, а не
переходит молча на конфигурацию сборки. Постоянный том остаётся привязан к
UID, который его заполнил, см. [Ключи ACME](#ключи-acme).

Обычный образ отказывает мастеру не от root ещё до того, как выполняется
конфигурация:

```text
the default image requires a root master for port 80 and the angie worker user; use the unprivileged image for rootless operation
```

Его порту 80 и директиве `user angie` нужен root; для запуска без root берите
непривилегированный образ, а не `--user`.

## Усиление запуска

### Корень только для чтения

Обоим вариантам нужна одна записываемая точка:

```sh
# Обычный образ

docker run --read-only --tmpfs /data:mode=1777 \
  6run0/angie:alpine

# Непривилегированный образ

docker run --read-only --tmpfs /data:mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges:true \
  6run0/angie:alpine-unprivileged
```

Обычному master также нужны смена пользователя worker-процессов и владельца
временных файлов; одной `NET_BIND_SERVICE` недостаточно. Чтобы убрать все
capabilities, используйте непривилегированный образ.

Оба Dockerfile снимают биты setuid и setgid со всех файлов файловой системы
образа, поэтому `su`, `passwd` и подобные программы не повышают права процесса
не от root (в Debian их несли 11 программ из shadow и util-linux).

При включённом ACME или дисковом кеше замените tmpfs постоянным
`-v angie-data:/data`. В `/data/acme` находятся закрытые ключи учётной записи и
сертификаты. Не монтируйте `/data/conf` отдельно.

### Ограничение сети

Публикуйте только нужный порт. Необязательный status listener по умолчанию
использует 8181 и намеренно не `EXPOSE`-ится. Для других контейнеров оставьте
его во внутренней сети; для хоста привяжите к loopback.

```sh
docker run -p 127.0.0.1:8080:8080 \
  6run0/angie:alpine-unprivileged
```

TLS-слушателя по умолчанию нет. Добавьте его в
`/etc/angie/custom/http.d` или завершайте TLS перед контейнером.

## Границы доверия конфигурации

`/etc/angie/custom` - доверенный код. Конфигурация Angie способна раскрыть
файлы, проксировать трафик, загрузить модули и ослабить контроль доступа.
Монтируйте её только для чтения и проверяйте изменения. Образ подключает только:

- `conf.d` в основном контексте;
- `http-conf.d` в контексте `http`;
- `http.d` для виртуальных хостов.

Каталоги должны быть проходимы, файлы - читаемы для worker. В обычном образе
успешная проверка файла root-мастером не доказывает, что worker `angie` прочтёт
его во время запроса.

## Ловушки конфигурации

Ни одна из них не даёт ошибки: `angie -t` проходит, проверка работоспособности
зелёная.

`/healthz` отвечает всякому, кто пришёл с loopback. `$_stock_loopback`
смотрит на `$realip_remote_addr`, TCP-адрес соседа до подмены real-IP, поэтому
`X-Forwarded-For: 127.0.0.1` его не проходит и при заданной
`ANGIE_REAL_IP_FROM` (измерено на образе 1.12.4 Alpine, 2026-10-23, с
`ANGIE_REAL_IP_FROM=172.17.0.0/16`: такой запрос с хоста получил `404`, обычный
запрос изнутри контейнера - `200`). Сосед на loopback проходит честно: сайдкар
или прокси в том же сетевом пространстве имён, а с ним и всё, что он
пропускает снаружи. Такой прокси не должен пробрасывать `/healthz`.
`allow`/`deny` не помогли бы: `return` этой точки отрабатывает на фазе
rewrite, до фазы access.

Переменные образа можно молча заменить. Переменная `$_stock_*`, объявленная
заново в `/etc/angie/custom`, побеждает переменную образа, `$_stock_loopback`
тоже, см.
[configuration.ru.md](configuration.ru.md#переменные-которые-объявляет-образ).

gzip сжимает проксируемые ответы независимо от заголовков апстрима
(`gzip_proxied any` в `020-gzip.conf`). Сжатие ответа, где рядом с секретом
отражается подконтрольный нападающему ввод, - предпосылка BREACH. Проксируя
содержимое за аутентификацией, ограничьте `gzip_proxied` или выключите сжатие
для таких location.

Все поставляемые форматы лога доступа пишут строку запроса: `path` - это
`$request_uri` в `json`, `logfmt`, их вариантах с GeoIP2 и `matomo`,
`extended` пишет `ru="$request_uri"`, `main` - `"$request"`. Секрет в URL
(`?token=`, `?api_key=`, идентификатор сессии) попадает в stdout контейнера.
Если секреты ходят в параметрах запроса, используйте свой формат с `$uri`. Путь
Console Light попадает туда же, поэтому для читающих журналы контейнера он не
секрет; защищает панель basic auth.

Status API при включении слушает `0.0.0.0:8181`, чтобы до него дотянулся
сборщик метрик из соседнего контейнера. Его единственная защита - то, что порт
не опубликован: ни `allow`, ни `deny`, ни аутентификации в сниппете нет. В
Kubernetes публикации тоже нет, порт по IP пода открыт каждому поду, пока его
не закроет NetworkPolicy. По той же причине `ANGIE_STATUS_API_PORT`, равный
публичному порту (80 у обычного, 8080 у непривилегированного), роняет старт:
на общем сокете запрос с `server_name` Status API в `Host` прошёл бы мимо
`return 444` перехватчика. Проверка знает только встроенный порт; совпадение со
своим слушателем из `/etc/angie/custom` остаётся на вас.

Заголовки безопасности не объединяются. Любой `add_header` в `server` или
`location`, даже про посторонний заголовок, заменяет унаследованный набор, и
заголовки `055-security-headers.conf` пропадают вместе с CORS и HSTS. Добавляя
свои, повторите и эти, см.
[troubleshooting.ru.md](troubleshooting.ru.md#25-заголовки-безопасности-пропали-в-моём-location).

`ANGIE_CORS_ASSETS_ENABLED` разрешает меньше, чем обещает имя. Значение
заголовка берётся из карты по типу содержимого ответа, а не по `Origin`
запроса: шрифты и картинки получают `Access-Control-Allow-Origin: *`,
документы, JSON и любой другой тип - никакого заголовка. Тумблер чинит шрифт,
который браузер отказывается брать с другого домена, и не открывает ваш API
чужим источникам. Обратная сторона: `*` у картинки позволяет скрипту с любой
страницы её прочитать, поэтому на сайте с картинками за аутентификацией
тумблер не включайте. При двух Angie в цепочке, у обоих с тумблером, заголовок
уходит дважды, а такой ответ браузер отвергает целиком; оставьте тумблер на
одном из них.

## Значения из окружения не попадают в конфигурацию как есть

Каждое значение, подставляемое в директиву, сначала проверяется по набору
символов или по списку значений: `GEOIP2_DB_COUNTRY`, `ANGIE_REAL_IP_FROM`,
`ANGIE_REAL_IP_HEADER`, `ANGIE_REAL_IP_RECURSIVE`, `ANGIE_STATUS_API_HOST`,
`ANGIE_STATUS_API_PORT`, `ANGIE_ACME_DIRECTORY`, `ANGIE_ACME_CLIENT`,
`ANGIE_ACME_CHALLENGE`, `ANGIE_ACME_EMAIL`, `ANGIE_ACME_HTTP_PORT`,
`ANGIE_HSTS_MAX_AGE`, `ANGIE_WORKER_SHUTDOWN_TIMEOUT`, `ANGIE_CONSOLE_PATH` и
`ANGIE_CONSOLE_HTPASSWD_FILE`. Допустимые наборы - в
[configuration.ru.md](configuration.ru.md#переменные-окружения) и в каждом
сообщении об отказе. Значение с посторонним символом роняет старт контейнера, а
не отрисовывается в конфигурацию; именно так закрыто внедрение конфигурации
через окружение.

## Console Light

Console Light раскрывает рабочую статистику. Сохраняйте три уровня защиты:

1. случайный `ANGIE_CONSOLE_PATH` минимум из 16 символов;
2. читаемый htpasswd в `ANGIE_CONSOLE_HTPASSWD_FILE`;
3. TLS перед публичным слушателем.

Сгенерируйте значения, не передавая пароль в окружении:

```sh
openssl rand -hex 16
printf 'admin:%s\n' "$(openssl passwd -6)" > console.htpasswd
chmod 0644 console.htpasswd
```

Смонтируйте каталог в `/etc/angie/custom:ro`. Значение
`ANGIE_CONSOLE_HTPASSWD_FILE=none` отключает аутентификацию и допустимо только
на отдельно защищённом приватном слушателе.

## Ключи ACME

Состояние ACME лежит в `/data/acme`. Защищайте постоянный том и его резервные
копии как секрет. Не используйте tmpfs: потеря состояния создаёт новый заказ
после пересоздания и может исчерпать лимиты CA. Первую настройку проверяйте на
тестовом CA.

Непривилегированный вариант не может слушать внутренний порт проверки ниже
1024: публикуйте порт хоста 80 на его внутренний 8080. Обычный вариант может
использовать стандартный порт 80.

## TLS

TLS-слушателя в поставке нет: ни один `server` не делает `listen ... ssl`, и в
`EXPOSE` только порт чистого HTTP. Активный по умолчанию `050-ssl.conf` задаёт
политику, которую любой свой TLS-слушатель наследует из контекста `http`:

- протоколы TLSv1.2 и TLSv1.3, умолчание Angie; нижней границы файл не
  закрепляет;
- для TLS 1.2 только шесть наборов ECDHE с AEAD из профиля Mozilla
  intermediate; наборы TLS 1.3 директива `ssl_ciphers` не задаёт;
- `ssl_session_tickets off`: ключ тикетов Angie держит до перезагрузки, и его
  утечка расшифровывает весь записанный трафик. Возобновление сессий идёт через
  общий `ssl_session_cache`.

Измерено на образе 1.12.4 Alpine (2026-10-23, клиент OpenSSL 3.5.8):
`openssl s_client -tls1_2 -cipher ECDHE-RSA-AES256-SHA` получает отказ
`SSL alert number 40`, без выбора шифра рукопожатие согласует
`ECDHE-RSA-AES256-GCM-SHA384`, тикета сессии сервер не выдаёт. Для старого
клиента с CBC-наборами `ssl_ciphers` переопределяется в его `server {}`.

Слушатель добавляется в `/etc/angie/custom/http.d` с путями к своим
сертификатам: порт 443 в обычном образе; 8443 в непривилегированном с
публикацией `-p 443:8443`, потому что привилегированный порт под мастером не от
root зависит от runtime, см. [configuration.ru.md](configuration.ru.md#порты).

## HSTS

HSTS - состояние браузера, а не просто заголовок ответа. До включения
`ANGIE_HSTS_ENABLED` убедитесь, что HTTPS будет работать весь срок и на всех
поддоменах, если задан `ANGIE_HSTS_INCLUDE_SUBDOMAINS=yes`.

Безопасное отключение:

1. оставьте тумблер включённым и задайте `ANGIE_HSTS_MAX_AGE=0`;
2. отдавайте этот заголовок по исправному HTTPS достаточно долго, чтобы его
   получили клиенты;
3. только затем выключите тумблер.

Немедленное удаление заголовка не очищает уже сохранённое состояние клиентов.

## Секреты

Не передавайте пароли, закрытые ключи и API credentials через окружение: они
видны при инспекции контейнера и часто в метаданных процессов. Подключайте
секретные файлы только для чтения или используйте механизм секретов runtime.
Ограничьте чтение баз GeoIP, TLS-материалов, htpasswd и состояния ACME только
нужными пользователями.
